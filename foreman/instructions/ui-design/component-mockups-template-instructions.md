## Section‑by‑section guidance
- **0) Overview** — Provide high-level project context and component statistics. Keep this section brief and factual.
- **1) Core Components** — Define essential UI components with complete state variations. Each component must include default, hover, active, error, loading, and disabled states using ASCII art mockups.
- **2) Data Display Components** — Focus on components that present data to users. Include empty state, loading state, and error state designs.
- **3) Form Components** — Cover all form-related components including validation states and multi-step flows.
- **4) Navigation Components** — Define navigation patterns for different screen sizes and contexts.
- **5) Modal & Dialog Components** — Specify overlay components and their interaction patterns.
- **6) Real-time Components** — Define components that display live updating data.
- **7) Mobile-Specific Components** — Cover touch-optimized components and gesture interactions.
- **8) Component Interaction States** — Define global interaction patterns across all components.
- **9) Component Cross-Reference Matrix** — Provide a comprehensive mapping of components to flows and requirements.
- **10) Design Tokens & Variables** — Define the design system tokens used throughout the components.
- **11) Animation & Transition Specifications** — Specify timing, easing, and animation behaviors.
- **12) Assumptions & Open Questions** — List any assumptions made and questions that need resolution.

## ASCII Art Guidelines
When creating component mockups:
- Use ASCII characters to represent UI elements
- Keep mockups consistent in style and proportions
- Use `┌─┐`, `│`, `└─┘` for borders and containers
- Use `[Button]` for interactive elements
- Use `●`, `○`, `▲`, `▼` for status indicators
- Use `████` for progress bars and loading states
- Include spacing to show layout and hierarchy
- Add comments with `←` arrows to explain elements
